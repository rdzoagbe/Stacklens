# Pre-filing eligibility note

Send this before drafting the long application. The guide's section 3 calls
this the single decision that everything else depends on: Innov'up excludes
projects relating to *logiciels métiers*, and Stacklens is software used by
businesses. The note argues why the proposed R&D falls under the *advanced
digital / AI* and *business security / sovereignty* priorities instead, and
asks the eight questions the guide lists so the answer comes back in writing.

**To:** aides.economiques@iledefrance.fr, and/or Bpifrance via contact.bpifrance.fr
("Je suis porteur de projet innovant").
**Attach:** nothing yet. Offer `02-technical-baseline.md` on request.
**Keep:** the sent email and the reply, dated, in the evidence folder.

Madame, Monsieur,

Je suis entrepreneur individuel (APE 58.29C — édition de logiciels applicatifs,
SIREN 104 838 727, établissement au 89 avenue Carnot, 93140 Bondy), éditeur de

**Le projet n'est pas le développement du logiciel Stacklens.** Le logiciel

> Peut-on reconstruire, à partir de données fragmentaires et hétérogènes
> (exports bancaires, annuaires d'identité, factures), l'environnement logiciel
> réel d'une organisation, en inférer l'utilisation effective des licences et
> les anomalies d'accès, et produire des recommandations explicables que des
> administrateurs peuvent appliquer en confiance — avec des taux d'erreur

Nous avons mesuré le point de départ. Sur un jeu de 72 lignes bancaires

vise à réduire ; elles ne sont pas des fonctionnalités à livrer mais des
questions ouvertes de traitement de données incomplètes, d'inférence,
d'explicabilité et de minimisation des données personnelles.

- *Numérique avancé / IA* : inférence sur données hétérogènes, détection

Le programme est structuré en six lots (modèle de données et découverte ;
inférence d'utilisation ; moteur de risque d'accès ; recommandations

## English rendering (for the founder's reference; do not send)

**Subject: Innov'up — pre-filing eligibility check — R&D project "SaaS
environment analysis engine" (sole trader, Bondy 93)**

I am a sole trader (APE 58.29C, software publishing; SIREN 104 838 727;
establishment at 89 avenue Carnot, 93140 Bondy), publisher of Stacklens, a SaaS
spend and access management service for small and mid-sized companies. Before
writing a full Innov'up application I want to check the eligibility of the
R&D project below against the *logiciels métiers* exclusion.

**The project is not the development of the Stacklens software.** The software
exists, is in production, and is not what is being requested. The project is a
12–18 month R&D and experimentation programme on an unresolved technical
question: can a company's real software environment be reconstructed from
fragmentary, heterogeneous data (bank exports, identity directories, invoices);
can actual licence utilisation and access anomalies be inferred from it; and
can explainable recommendations be produced that administrators can safely
act on, with measured error rates?

We have measured the starting point. On a labelled set of 72 bank lines (38
software subscriptions, 34 non-software), the current rule-based engine
identifies software subscriptions with 71% precision and 82% recall; it
recognises billing cadence in 73% of labelled sequences; it produces
documented false positives (advertising spend read as subscriptions, name
collisions, usage-based billing read as a price rise). These dated,
reproducible measurements are the technical uncertainty the project reduces.
They are not features to deliver but open questions of incomplete-data
processing, inference, explainability and personal-data minimisation.

The programme has six work packages, each with a KPI measured before and
after. The request would be subvention only, no repayable financing, for a
project budget of roughly €30–75k depending on scope; work starts only after
submission. The eight questions follow the guide's section 23 exactly.
